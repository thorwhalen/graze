graze.guarded¶

Guarded fetch with a pinned transport — an SSRF-safe GET for caller-supplied URLs.

Fetching a URL that someone else handed you is a server-side request forgery hole: the URL can point at localhost, at a private network, or at cloud metadata (169.254.169.254). The usual guard — resolve the host, check the addresses, then let an HTTP client connect — has two gaps:

  • DNS rebinding. The client resolves the host again when it connects, and an attacker’s DNS answers “public” to the check and 127.0.0.1 to the connect.

  • Redirects. A public URL answers 302 Location: http://169.254.169.254/, and a client that follows redirects by itself never shows the hop to the guard.

This module closes both by owning the transport. Each hop’s host is resolved once, every resolved address is checked, and the socket is opened to exactly the address that was checked — while the request still carries the original Host header and the TLS handshake still sends the original name (SNI) and verifies the certificate against it. Redirects are never followed by a library; each Location goes back through the same check.

>>> body = guarded_fetch('https://example.com/data.json')
>>> guarded_fetch('http://169.254.169.254/latest/meta-data/')
Traceback (most recent call last):
    ...
graze.guarded.UnsafeTarget: refusing http://169.254.169.254/latest/meta-data/: address 169.254.169.254 is not allowed
>>> guarded_fetch('file:///etc/passwd')
Traceback (most recent call last):
    ...
graze.guarded.UnsafeTarget: refusing file:///etc/passwd: scheme 'file' is not allowed (allowed: https, http)

guarded_fetch() returns the body as bytes. guarded_open() returns a GuardedResponse to stream from (iter_chunks) when the body is large, and exposes the final URL, the status, the headers, and the address actually connected to.

timeout is a wall-clock budget for the whole fetch — resolution, connection, TLS handshake, redirects, headers and body. A per-read socket timeout alone is not one: a server trickling a byte just inside it can hold a worker for as long as it likes. So on top of the socket timeouts, a watchdog shuts the socket down when the budget runs out.

The seams, all keyword-only:

  • is_allowed_address — the address policy. default_public_only() by default; pass an allow-list for tests or for a self-hosted deployment that must reach a LAN host.

  • resolver — host name to addresses. system_resolver() (getaddrinfo) by default; a fake one makes rebinding testable offline.

  • connector and ssl_context — how the pinned socket is opened and wrapped.

Like graze.share_links and graze.content_kind, this module uses the standard library only (http.client, ssl, socket, ipaddress). It reads no proxy settings from the environment, on purpose: a proxy would resolve the host itself, and the pin would be meaningless.

class graze.guarded.GuardedResponse(url, status, reason, headers, address, max_bytes, _response, _connection, _watchdog, _bytes_read=0)[source]¶

Bases: object

An open response from guarded_open(), with its budgets still enforced.

Use it as a context manager, and read it with iter_chunks() (streaming) or read() (everything). Reading past max_bytes or past the deadline raises FetchLimitExceeded. max_bytes counts bytes as they arrive, so a caller who overrides Accept-Encoding caps the compressed size. The time budget keeps running while the caller handles a chunk, so a slow consumer (writing to a slow disk, say) should ask for a timeout that covers its own work too.

graze.guarded.default_public_only(ip)[source]¶

True iff ip is a globally routable unicast address.

Refuses loopback, private, link-local (cloud metadata lives there), carrier-grade NAT, reserved, unspecified and multicast addresses. An IPv6 address that embeds an IPv4 one (::ffff:127.0.0.1, 6to4, Teredo, NAT64, SIIT) is judged by the embedded address too — explicitly, because ipaddress only learned to look through IPv4-mapped addresses in CPython 3.10.14 / 3.11.9 / 3.12.3 (CVE-2024-4032).

>>> default_public_only(ipaddress.ip_address('93.184.216.34'))
True
>>> [default_public_only(ipaddress.ip_address(a)) for a in
...  ('127.0.0.1', '10.0.0.1', '169.254.169.254', '::1', '::ffff:127.0.0.1')]
[False, False, False, False, False]

Open url through the guard and return the response, body not yet read.

Every hop — the URL and each redirect — is checked: scheme in allow_schemes, port in allow_ports (None allows any), host resolved once by resolver, every address accepted by is_allowed_address, and the socket opened to one of exactly those addresses. timeout is a wall-clock budget for the whole fetch, including reading the body; max_bytes caps the body.

Redirects follow browser rules (303, and 301/302 after a POST, become a GET without a body). When a redirect leaves the original origin, only the caller headers in CROSS_ORIGIN_SAFE_HEADERS go with it.

Return type:

GuardedResponse
